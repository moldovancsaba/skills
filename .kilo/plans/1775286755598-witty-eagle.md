## Trigger Logic (NEW DATA ONLY)

1. **Track last sync timestamp** in database or file
2. **Query for new data since last sync**:
   ```sql
   SELECT * FROM "Product" WHERE "createdAt" > $lastSync
   UNION ALL
   SELECT * FROM "Customer" WHERE "createdAt" > $lastSync
   UNION ALL
   SELECT * FROM "Competitor" WHERE "createdAt" > $lastSync
   ```
3. **Only run AI if new data exists** - skip if no new data
4. **Update lastSync after processing**

## Smarter Deduplication

1. **Normalize titles** (lowercase, remove common words like "the", "and", "for", "with")
2. **Tokenize and compare** using simple Jaccard similarity
3. **Threshold**: 0.7 similarity = duplicate
4. **Example**:
   - "Boost SEO Strategy" ≈ "SEO and Keyword Strategy" → duplicate

```js
function similarity(a, b) {
  const tokenA = normalize(a).split(' ');
  const tokenB = normalize(b).split(' ');
  const common = tokenA.filter(t => tokenB.includes(t));
  return common.length / Math.max(tokenA.length, tokenB.length);
}

function normalize(s) {
  return s.toLowerCase()
    .replace(/^(a|an|the|and|or|for|with|to|of)\s+/g, '')
    .replace(/[^\w\s]/g, '');
}
```

```

    ↓ (no new data) ──→ Skip, wait for next poll
```

## CRITICAL: Unified Design System Fix

### Problem

1. **Inconsistent UI** - Some components use shadcn-ui components, others use hardcoded classNames
2. **Dark mode broken** - Input fields show white text on white background in dark mode
3. **Maintenance nightmare** - No clear pattern for designers/developers
4. **Legacy code** - Old pages use hardcoded `className="input"` which has limited styling

### Root Cause Analysis

**Pattern 1: shadcn-ui components** (GOOD)
```tsx
// Uses CSS variables: border-input, bg-background, text-foreground
<Input className="..." />
```

**Pattern 2: Inline Tailwind** (INCONSISTENT)
```tsx
// Missing text color, relies on CSS variables only
<input className="flex h-12 rounded-md border border-input bg-background px-3 py-2 text-sm" />
```

**Pattern 3: CSS class** (BROKEN)
```tsx
// Relies on .input CSS class that may not have proper dark mode styling
<input className="input" />
```

### Solution Plan

#### Phase 1: Fix globals.css

Update CSS variables to ensure proper dark mode:
```css
/* Force text color in inputs for all themes */
@layer base {
  input, textarea, select {
    @apply text-foreground;
  }
}
```

#### Phase 2: Create Unified Form Components

Create a single source of truth in `src/components/ui/form-fields.tsx`:

```tsx
// Unified Input that always works in dark mode
export function FormInput({ ...props }) {
  return (
    <Input 
      {...props}
      // Always include explicit text color
      className={cn(props.className, "text-foreground")}
    />
  )
}

// Unified Textarea
export function FormTextarea({ ...props }) {
  return (
    <Textarea 
      {...props}
      className={cn(props.className, "text-foreground")}
    />
  )
}
```

#### Phase 3: Audit and Replace

Find all hardcoded patterns and replace with unified components:
